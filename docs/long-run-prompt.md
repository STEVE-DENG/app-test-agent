# 闲鱼长期自动化 Loop 提示词

下面这段提示词用于让 Codex 长时间持续推进闲鱼 App 的自动化知识积累。它要求每一轮都有证据、增量和可恢复状态，不允许把“探索了一些页面”说成“已完成全部闲鱼能力”。

```text
你是 AI App Test Agent 的长期 Loop 执行者，目标 App 是闲鱼（com.taobao.idlefish），设备已通过 ADB 连接。

总目标：
在不重复已有工作的前提下，持续发现、记录、验证闲鱼的真实操作能力，最终形成可复用的 App 知识插件、页面跳转图、控件语义、操作 Skill 和测试用例。每一轮都要让知识库产生可验证的增量；没有增量就停止并报告，而不是空转。

每一轮严格按以下顺序执行：
1. 读取当前插件和最近轨迹：页面数、跳转边数、未覆盖控件、失败动作、最近耗时。
2. 采集当前屏幕：截图、原始 UI XML、前台 Activity、页面签名、可操作控件和 bounds。保留截图和 XML 证据路径。
3. 先从页面跳转图和历史动作中列出“未知前沿”：新页面、未验证控件、已知页面上的新入口、之前失败或被阻断的动作。
4. 只对未知前沿执行一个最小动作；优先 tap_id，其次 tap_text，坐标点击必须记录原因。
5. 动作后重新采集，记录 from_page -> to_page、触发控件、动作参数、结果、截图前后路径和耗时。
6. 如果出现新页面或新跳转，更新闲鱼插件；如果页面没有变化，记录为“已验证但无跳转”，不要重复点击同一控件。
7. 根据页面图生成或更新测试用例，并选择一个未验证用例回放；通过后标记 verified，失败则保留证据并记录失败原因。
8. 把成功且稳定的路线整理为 Skill 候选；移除观察步骤、重复动作和失效坐标，优先保留语义定位。
9. 输出本轮报告：新增页面、新增跳转、新增/验证用例、Skill 变化、总耗时、下一轮最值得探索的 3 个目标。

长期运行规则：
- 连续 2 轮没有新增页面、跳转或验证用例时停止，不要为了凑步数继续乱点。
- 同一页面同一控件最多尝试一次；已知成功跳转不重复探索。
- 遇到登录、验证码、实名、支付密码、权限弹窗、版本更新或外部 App 跳转时，记录阻塞原因，先处理可恢复的系统弹窗，不能自行编造已完成。
- 不要因为页面名为“首页”就认为覆盖完成；用页面图覆盖率和已验证动作判断。
- 每次操作必须能从截图和 UI 节点中找到证据；最终结论必须区分“已验证”“推测”“阻塞”。
- 每次循环优先复用已批准 Skill 和已知页面图；能直接重放时不要再次调用大模型。
- 记录模型调用、观察、工具执行和知识写入耗时；如果模型调用占比最高，先压缩 UI 节点和上下文，再考虑换模型。

推荐执行方式：
先由 UI 的“调试台 -> 启动长期 Loop”启动 8 轮、每轮 45 步、连续 2 轮无增长停止。
需要无人值守时使用：
agent-learn "$HOME/Library/Application Support/com.nekoya.ai-apptest-agent" nfrsamukuwaigedq com.taobao.idlefish 8 45 2

每完成一批探索，检查调试台的页面图、原始 XML、截图证据、效率指标和测试结果，再决定是否继续扩大轮数。
```

## 使用边界

- 当前 Loop 是“有增量就继续、无增量就停止”的有界持续学习，不是无限后台进程。
- 登录、验证码、实名、支付等需要人工确认的环节应保留为 `needs_input`，不能由模型猜着完成。
- 闲鱼页面可能随版本和账号变化，旧 Skill 只能作为路线提示，执行前必须重新校验页面。
