### 2026-10-28 OCR 与模型提速

- 新增 Apple Vision OCR helper，提取文字、像素 bounds、归一化 bounds 和置信度；真机闲鱼首页采集 35 个文本块，OCR 约 378ms。
- OCR 文本块会自动关联当前 UI 树节点：本次 29 个成功关联，6 个保留为“仅视觉”证据；每个截图同时保存 `*.ocr.json`。
- 调试台新增 OCR 文本块列表、截图叠加 OCR 框、置信度、坐标、匹配节点和复制 OCR JSON；工作台画布也可点击 OCR 框回到对应 UI 节点。
- `tap_text` 定位链路改为 `UI 树 -> 重新 dump UI 树 -> OCR 视觉坐标`，结果记录 `locatorSource`、置信度和 bounds，便于定位失败复盘。
- 每帧额外生成 900px JPEG 作为模型视觉输入；本次模型图约 94-101KB，原 PNG 约 2.3-2.7MB，输入体积降到约 4%。
- 模型 Prompt 的 UI 节点和 OCR 摘要改为紧凑 JSON；OCR 只发送 UI 树缺失或语义不一致的高价值块。
- 真机任务“返回闲鱼首页”最终 5 步、1 次模型调用完成：模型耗时 7.9s，总步骤耗时 30.5s；对比首次 OCR 版本 5 步、3 次模型调用、模型耗时 116s、总步骤耗时 149s，端到端约提速 4.9 倍。
- 最终模型 Prompt 为 11,112 字符，较早期约 18,729-19,315 字符下降约 41%；仍保留 56 个 UI 节点和 OCR 缺失文本证据。
- `npm run build`、`cargo check`、`cargo test`（16 项）通过。
